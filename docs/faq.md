# 常見問答與疑難排解（FAQ）

在創作與打譜過程中，無論是手動輸入還是搭配 AI 生成，最常見的挫折往往來自「小節拍數對不上」、「忘記時值倍率語法」或是「調性概念混淆」。

本篇整理了 TMD 使用者最常遇到的語法地雷、排錯心法與實用技巧。

---

## 1. 最常見語法錯誤：忘記寫倍率 `<4*>` 或 `<8*>`

這是所有 TMD 新手（以及大型語言模型 AI）**最容易踩中、機率高達 80% 的超級大雷區**！

### 1.1 問題成因：什麼是「持續性倍率」？
在 TMD 中，角括號倍率 `<4*>`、`<8*>`、`<16*>` 是**持續生效（Sticky）**的狀態切換，代表「**從現在開始，後面所有數字的預設時值都是幾分音符**」。

常見的錯誤案例是：使用者想寫一串八分音符，但手滑寫成：
```tmd
# ❌ 錯誤示範：忘了切換倍率（預設是四分音符）
1 2 3 4 | 5 6 7 1 |  # 原本心裡想的是八分音符跑動，結果被當成 8 個四分音符！
```
或者在八分音符跑完之後，想寫一個四分音符，卻忘了切回 `<4*>`：
```tmd
# ❌ 錯誤示範：跑完八分音符後，要寫四分音符卻忘了切回 <4*>
<8*> 1 2 3 4 5 6 <4*> 1 |  # 如果最後這個 1 忘了寫 <4*>，整小節就只會有 3.5 拍！
```

### 1.2 經典時值對照速查表
| 想表達的音符 | TMD 正確寫法 | 佔 4/4 拍拍數 |
| :--- | :--- | :--- |
| **全音符（4 拍）** | `<4*> 1 - - -` 或 `<1*> 1` | 4 拍 |
| **二分音符（2 拍）** | `<4*> 1 -` 或 `<2*> 1` | 2 拍 |
| **四分音符（1 拍）** | `<4*> 1` | 1 拍 |
| **八分音符（半拍）** | `<8*> 1` | 0.5 拍 |
| **十六分音符（1/4 拍）** | `<16*> 1` | 0.25 拍 |
| **附點四分音符（1.5 拍）**| `<8*> 1 - -` 或 `<4*> 1.` | 1.5 拍 |
| **附點八分音符（0.75 拍）**| `<16*> 1 - -` 或 `<8*> 1.` | 0.75 拍 |

> **排錯金句**：**「進八分寫 `<8*>`，回四分切 `<4*>`，寫完小節數一數！」**

## 2. 小節長度校驗失敗（Measure Length Mismatch）

為了確保樂譜時值精確並能順利轉換為 MIDI 與 MusicXML，TMD 的小節檢查相當嚴格。如果小節拍數不等於當前拍號（例如在 4/4 拍中必須剛好湊滿 4.0 拍），編譯器與 VS Code 就會標記錯誤：
`Measure 5 has 3.5 beats (expected 4.0 beats)`

### 2.1 常見原因一：延音線 `-` 與休止符 `0` 數量算錯
- **錯誤**：`<4*> 1 - - |`（四分音符 + 兩個延音 = 3 拍，但拍號是 4/4 拍，少了 1 拍）。
- **修正**：`<4*> 1 - - - |`（補足 4 拍）。

### 2.2 常見原因二：三連音括號漏掉音符
三連音語法為 `[1 2 3]`。在預設四分音符環境下，`[1 2 3]` 剛好等於「兩拍內塞三個等長音」。
- **錯誤**：`[1 2]`（括號內只有兩個音符，造成拍數計算異常）。
- **正確**：三連音必須填滿標準三等分，或是使用休息符 `[1 2 0]`。

### 2.3 排錯第一原則：隨時注意錯誤訊息（Watch Your Errors）
無論你是在命令列、Web Studio 還是 VS Code 編輯 TMD，**隨時盯緊系統提示的錯誤訊息，是省下 90% 排錯時間的關鍵習慣**：
- **VS Code**：下方狀態列與「問題（Problems）」面板會即時列出所有小節拍數異常，並在編輯區以紅色波浪線精準標記錯誤行號。不要累積了幾十小節才一次檢查，每寫完一個樂句就順手看一下問題面板。
- **CLI**：隨時執行 `tmd check song.tmd`，終端機會直接告訴你：
  ```text
  Error: Measure 5 has 3.5 beats (expected 4.0 beats)
  ```
  這代表「**第 5 小節少了半拍**」，你立刻就能知道要回頭檢查該小節是漏了八分音符、延音線 `-`，還是忘了切回 `<4*>`。

### 2.4 善用 AI 自動修正錯誤（Let AI Fix It For You）
如果你手邊有一長段旋律算不清楚拍子，或是 AI 剛生成出來的樂譜小節有些微誤差，**完全不需要自己拿計算機手動逐拍硬算**！你可以直接讓 AI 幫你修正：

1. **在 Web Studio 中「一鍵修復」**：
   - 點擊工具列或編輯區上方的 **「Ask AI to Fix」** 按鈕。
   - 系統會將當前樂譜與編譯器回報的具體錯誤小節整合成 Prompt，自動送交 AI 修補延音線或時值，並在介面中提供即時差異（Diff）預覽，確認無誤後一鍵套用。
2. **在 VS Code / Copilot Chat 中發問**：
   - 選取報錯的小節，在對話框輸入：
     > `@tmd 第 5 小節目前回報只有 3.5 拍，請保持旋律動機，幫我補足為 4/4 拍標準 4 拍。`
3. **在終端機或一般 Chat AI 中餵入錯誤訊息**：
   - 直接把 CLI 輸出的錯誤訊息貼給 Claude / ChatGPT：
     > 「這段 TMD 樂譜在編譯時報錯：`Measure 5 has 3.5 beats (expected 4.0)`，請幫我修正小節中的時值倍率，確保每個小節都精準等於 4 拍。」
   - AI 極度擅長理解這類「有明確數學反饋」的語法修正，通常數秒內就能給出完美的修正版本。

## 3. 調性與基準音高混淆（`key=` vs `?=`）

許多初學者在設定調性時會感到困惑：「為什麼有了 `key=C`，後面又看到 `?=0`？」

### 3.1 兩者的核心區別
- **`key=`（聲明調性）**：
  告訴排版引擎與音樂家「這首歌是甚麼調」（例如 `key=D` 代表 D 大調，樂譜開頭會有兩個升記號升 F、升 C）。
- **`?=`（基準音高 / Pitch Center）**：
  告訴合成器與播放引擎「簡譜的數字 1 對應到 MIDI 音高的哪一個半音」（以 C4 中央 C 為 0）。
  - `?=0`：1 = C
  - `?=2`：1 = D
  - `?=4`：1 = E
  - `?=-3`：1 = A

### 3.2 為什麼要有首調（Movable-do）設計？
TMD 採用簡譜哲學。只要你寫 `1 2 3 1`，這段旋律在任何調性下聽起來都是 *Do-Re-Mi-Do*。
當你想把整首歌升一個全音演唱時：
- **你不需要重寫任何音符！**
- 只需要把開頭的 `?=0` 改成 `?=2`，整首歌立刻無損移調（Transpose）。

## 4. 第 10 軌鼓組（Channel 10 Drums）不出聲或音高不對？

在標準 MIDI 規範中，**Channel 10（第 10 軌）是固定的打擊樂專用軌道**。

### 4.1 為什麼第 10 軌不能唱旋律？
在第 10 軌中，音高數字不再代表 Do-Re-Mi，而是對應到 **通用 MIDI 鼓組鍵位（GM Drum Map）**：
- `1`、`2` 等音高會直接觸發特定打擊樂器（如 35/36 為大鼓 Kick、38/40 為小鼓 Snare、42 為閉合鈸 Closed Hi-Hat）。
- 如果你在第 10 軌試圖寫鋼琴旋律，聽到的只會是一串雜亂的鼓點敲擊聲。

### 4.2 正確宣告方式
如果要寫鼓組，請務必將軌道指定至 Channel 10：
```tmd
V:10 channel=10
<8*> 36 42 38 42 | 36 42 38 42 |  # 標準動態大鼓、Hi-Hat 與小鼓
```

## 5. 跨小節延音線（Tie）的常見誤用

當一個音符要跨越小節線時：
- **正確寫法**：在前一小節結尾寫出音符，在後一小節開頭使用延音線 `-`：
  ```tmd
  <4*> 1 2 3 4 | - 3 2 1 |  # 第一小節第 4 拍的 4 連續延伸到第二小節第 1 拍
  ```
- **避免寫法**：直接在小節線上方或兩端任意加底線，TMD 會把 `-` 視為延續上一小節最後一個發聲的音高。

## 6. 音高升降與高低八度符號順序

TMD 的音高修飾符規則非常直覺：
- **高低八度**：單引號 `'` 代表高八度，逗號 `,` 代表低八度。可以疊加（如 `1''` 高兩個八度、`5,,` 低兩個八度）。
- **臨時升降記號**：`^` 代表升記號（Sharp），`_` 代表降記號（Flat），`=` 代表還原記號（Natural）。

### 正確寫法範例：
- `1'^`（高八度的升 Do）
- `3,_`（低八度的降 Mi）
- 順序即使稍微顛倒，TMD 容錯解析器多半能辨識，但最標準的推薦寫法是先標八度再標升降記號。

## 7. Humming 哼唱識別辨識率低？

在 TMD Web Studio 裡使用 Basic Pitch 哼唱轉 TMD 時，若識別出的音符破碎或節奏混亂：

1. **請務必佩戴耳機**：避免喇叭放出的伴奏或點擊聲（Click）被麥克風重複收錄。
2. **使用清晰的「嗒（Da）」或「嘟（Du）」發音**：不要用含糊的氣音或「啊～」，發音起音（Attack）越乾脆，音符切分越精準。
3. **音準穩定**：避免大幅度的滑音（Portamento），盡量像敲鍵盤一樣穩定在目標音高上。
4. **辨識後利用 Studio 工具一鍵重構**：識別完成後，點擊「量化（Quantize）」或「重新對齊小節」，即可自動撫平細微的時間差。
